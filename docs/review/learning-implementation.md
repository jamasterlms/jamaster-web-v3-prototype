The source level setting loads the global setting and submits normalized levels with `updateLevelSettings`; ordinary selectors load `/admin/levels`. The approved local implementation persists the same global shape in `settings.levelCatalog`, without introducing an API or authorization layer. Source UI uses level names and sublevel titles in group/registration values.

Source form schemas sometimes use `parseInt` for period numeric strings and unrestricted numeric order for global levels. Local validation deliberately accepts only nonnegative integers (duration >= 1), avoiding silent truncation. Local duplicate-name/ID, parent-ID and linked-deletion guards protect existing references.

## Implementation and integration

- `learning-page.tsx` keeps `LearningPage({route})`; four dedicated pages now supply their own fields, columns and previews. Shared list/form components provide adapted shadcn tables, mobile cards with the same actions, required sections before optional fields, inline validation, fixed action footer and preview before save.
- `learning-model.ts` adapts legacy rows to discriminated records. The original cells remain available; row index 5 stores a stable ID and index 6 stores versioned structured metadata. Saving materializes identities across all four catalogs before renames/inserts. The previously exposed `2026-fall` period ID remains compatible.
- `useLearningData()` is read-only and requires only WorkspaceProvider. It returns `educations`, `periods`, `programTerms`, `units`, `programs`, `academicTerms` and global `levels`. `useLearningCatalog()` adds mutations and live usage from OperationsProvider.
- Education rename propagates current course labels to groups, pricing plans and students. Source-shaped IDs remain stable. Historical sale/contract snapshots retain their original labels. Pricing usage and active-student counts are calculated from current records; the old manual active-student input is removed.
- `level-model.ts` provides `CatalogLevel`, `CatalogSubLevel`, pure parsing, validation and deletion helpers. `level-catalog.tsx` exports Workspace-only `useLevelCatalog(): CatalogLevel[]`; `level-settings.tsx` reexports it and exports `LevelSettings` for `/super/settings?tab=level`.
- Global migration uses only observed education-level names and student profile pairs. The first settings editor also includes actual saved group pairs. Saved global data is authoritative; empty or deleted choices are not repopulated from observations. No `.1`/`.2` names are generated. Existing IDs, titles, order, activity and timestamp fields are retained.
- Global level/sublevel rename updates current group and student labels. Before a rename, observed legacy curriculum links are persisted by global ID. Curriculum optional level choices use the global catalog; changing education does not invalidate an unrelated global level. Changing level clears its sublevel.
- Deleting linked education, duration, program-term, level or sublevel records reports the relationship and offers deactivation. Level deletion also checks curriculum references. The parent agent integrates live choices and validation into group, registration, pricing and settings routes; those files are outside this change's ownership.

## Preserved extensions and data limits

- Planned lesson counts and optional education/level/sublevel links in curriculum, plus education lesson counts and program-term education links, are preserved prototype extensions. They are not represented as fields from the source forms. Legacy level names on education remain read-only metadata; global settings manage active choices.
- Legacy education records have no reliable type; legacy calendar-style period rows have no reliable duration. They remain visibly unspecified until edited. Calendar cells are retained and are never guessed into a duration. Existing program-term Turkish dates are converted only when valid.
- Legacy curriculum rows lack a program-term ID. The editor requires the user to choose a real saved term. Education names resolve only to a unique normalized match; level titles use exact matches. Ambiguous or unresolved labels remain visible instead of being guessed.
- The local prototype has no populated source program or academic-term datasets. Optional selectors read existing `moduleRows.programs` and `moduleRows['academic-terms']` if present, otherwise remain empty with a short explanation. Existing unknown IDs are preserved during editing. Creating those independent source catalogs is outside this bounded task.
- Until the global setting is first saved, Workspace-only choice hooks cannot read the separate Operations store's group-only vocabulary. Existing group values remain preserved by the consuming forms; opening and saving LevelSettings migrates those observed pairs explicitly.
